# 設定ファイルの説明

設定は3つの YAML に書きます（#96）。**どれも git に入りません**（`*.sample.yml` だけが入っています）。
サンプルを写して使ってください。

| ファイル | 何を書くか | 読むもの |
|---|---|---|
| [`config/app_settings.yml`](#1-アプリ設定-configapp_settingsyml) | DB の場所・写真の置き場所・出力先・ルールの場所 | すべてのコマンドと GUI |
| [`config/rule.yml`](#2-抽出ルール-configruleyml) | `select` がどの写真を何枚、どの順で選ぶか | `photoarchive select`・GUI の「写真の選定」タブ |
| [`config/private_terms.yml`](#3-公開しない語-configprivate_termsyml) | リポジトリに書いてはいけない語（家族の名前・パスなど）と、置き換える変数 | コミット前の検査（開発するときだけ） |

```bash
cp config/app_settings.sample.yml config/app_settings.yml
cp config/rule.sample.yml config/rule.yml
cp config/private_terms.sample.yml config/private_terms.yml   # 開発するときだけ
```

**JSON は読みません**（#27）。以前の `config/app_settings.json` や `.json` のルールが残っていると、YAML へ書き直すよう促して止まります。
JSON の中身は YAML として読めるので、**空白で字下げしていれば**拡張子を変えるだけで移れます（YAML はタブで字下げできません）。

設計の理由や経緯は仕様書にあります（§2.2・§12.1・§9.2）。この文書は、書くときに引く一覧です。

## 1. アプリ設定 `config/app_settings.yml`

### どこを探すか

次の順に探し、**最初に見つかった1つ**を使います。リポジトリ以外のディレクトリから実行しても効きます。

1. 環境変数 `PHOTOARCHIVE_CONFIG` が指すファイル
2. カレントディレクトリの `config/app_settings.yml`
3. リポジトリ直下の `config/app_settings.yml`（`pip install -e .` で入れたときだけ）

見つからない・読めないときは**空の設定として動きます**（コマンドの引数だけで動かせます）。どこを探したかは `--log-level INFO` で出ます。

### キー

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `database_path` | パス | なし | SQLite のデータベース。**無いと、`--db` を付けないコマンドは止まります** |
| `source_roots` | パスの配列 | なし | 写真の置き場所（root）。複数書けます。1つなら文字列でも構いません |
| `output_root` | パス | なし | `select` のコピー先。**`select` 専用にしてください**（実行のたびに、直下のファイルを全部消してからコピーします） |
| `rule_path` | パス | なし | 抽出ルールのファイル（下の 2）。ふつうは `config/rule.yml` |
| `dlib_model_dir` | パス | なし | dlib の学習済みモデルを手で置いたディレクトリ（任意。いまの特徴量は ArcFace なので、ふつうは要りません） |

`source_roots` について:

- **共通の親を書かないでください。** たとえば `/mnt/nas/family/Photo` と `/mnt/nas/share/phone` を取り込みたいときに `/mnt/nas` と書くと、関係の無いフォルダまで取り込みます。**入れ子になった root は止めます**
- 以前の `source_root:`（1つだけのキー）は読みません。残っていると警告が出るので、`source_roots:` に書き直してください
- 設定に無いとき、`scan`・`assess`・`select` は**DB に記録された root**（前に `scan` が走査し終えた root）を使います。`convert-heic` は使いません（`--source` か設定が要ります）

### コマンドの引数との関係

**引数が設定より優先します。**

| 設定のキー | 上書きする引数 | 引数を持つコマンド |
|---|---|---|
| `database_path` | `--db` | `convert-heic` 以外の全部と `photoarchive-gui` |
| `source_roots` | `--source`（何度でも書けます） | `scan`・`assess`・`convert-heic`・`select` |
| `output_root` | `--output` | `select` |
| `rule_path` | `--rule` | `select` |

GUI には `--db` しかありません。写真の選定タブの出力先とルールは、設定の `output_root` と `rule_path` を使います。

### 相対パス

相対パスは**コマンドを実行したディレクトリ**から解きます。リポジトリ直下で実行するなら `data/photoarchive.db` のように書けます。
例外は GUI の `source_roots` で、こちらは設定ファイルの置き場所（`config/` の1つ上）から解きます（プレビューのフォルダ名を短く出すためだけに使います）。
別のディレクトリから実行するなら、絶対パスで書くのが確実です。

### 環境変数

| 環境変数 | 意味 |
|---|---|
| `PHOTOARCHIVE_CONFIG` | 設定ファイルの場所（探す順の 1） |
| `PHOTOARCHIVE_ONNX_MODEL_DIR` | ArcFace・Face Landmarker・MUSIQ・NIMA のモデルを置いたディレクトリ。無ければ `PHOTOARCHIVE_DLIB_MODEL_DIR`、リポジトリ直下の `models/` の順に探します |
| `PHOTOARCHIVE_DLIB_MODEL_DIR` | dlib のモデルの置き場所。設定の `dlib_model_dir` より優先します |

## 2. 抽出ルール `config/rule.yml`

`select` が**どの写真を、どの順で、何枚**選ぶかを書きます。どのキーも省略できます（省略すると下の既定）。
**空のファイルなら、全部既定で全部の写真を選びます。**

```yaml
date:
  start: 2000-01-01
  end: 2025-12-31
family_only: true
count_per_year: 30
include_video: true
remove_duplicate: true
remove_similar: true
include_auto_assigned: true
```

### 絞り込み

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `date.start` / `date.end` | 日付 | 制限なし | 撮影日時の範囲。**`end` はその日の終わりまで含みます。** 引用符はあってもなくても読めます。撮影日時が無い写真はフォルダ名から起こした撮影時期で見て、その区間が**まるごと範囲に入るときだけ**選びます。どちらも無ければファイルの作成日時で見ます |
| `family_only` | 真偽 | `false` | 家族の顔が写っている写真だけにする。**写りの良し悪しでは絞りません**（ボケた家族の写真も残り、並びで後ろへ回ります）。親しい人だけの写真は家族の写真に数えません |
| `include_auto_assigned` | 真偽 | `true` | `match` の自動割り当ての顔も家族として数える。`false` なら GUI で割り当てた顔（手本）だけで数えます |
| `include_video` | 真偽 | `true` | 動画も選ぶ |
| `remove_duplicate` | 真偽 | `false` | ファイルの中身がまったく同じ写真を1枚にする |

### 似た写真を束ねる

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `remove_similar` | 真偽 | `true` | 同じ場面の連写や、見た目の似た写真を、並びのいちばん上の1枚にする。同じ年に選んだ写真の写し（別の端末のフォルダ・送られてきた写真）も外します |
| `similar_seconds` | 0 以上の数 | `10` | **日付をまたぐ**連写をつなぐ撮影の間隔（秒）。同じ日の写真は間隔によらず比べます |
| `similar_distance` | 0 以上（0〜64 で効く） | `16` | 同じ場面とみなす見た目の近さ。**小さいほど厳しく**（束ねにくく）なります |
| `similar_far_distance` | 0 以上（0〜64 で効く） | `14` | 撮影時刻の離れた2枚（間隔が `similar_seconds` を超える）を同じ場面とみなす近さ |
| `copy_distance` | 0 以上（0〜64 で効く） | `9` | 同じ年にすでに選んだ写真の写しとみなす近さ |

詳しい束ね方は仕様書 §11.2 にあります。

### 年ごとの枚数 `count_per_year`

**数を1つ書くと、全部の年に同じ枚数**を選びます。`0` か省略で、枚数の制限はありません。

```yaml
count_per_year: 30
```

**年と枚数の対応で書くと、年ごとに変えられます。** このときは**書いていない年からは選びません。**

```yaml
count_per_year:
  2018: 50
  2019: 30
  unknown: 10   # 撮影した年の分からない写真（書かなければ選ばない）
  2027+: 30     # 2027 年以降で、上に書いていない年（1つだけ書ける）
```

`2027+` はこれから増える年のためのものです。年が変わったら、GUI の年の表で設定し直してください。
年は撮影日時から、無ければフォルダ名から起こした撮影時期から決めます。対応の中で枚数を `0` にした年からも選びません。

### 並びの重み `weights`

**写真に点を付け、点の高い順に選びます。** 重みはその点の配分です。**書いていない項目は既定値**のままです。

```yaml
weights:
  sharpness: 0.35
  member_bonus: 20
```

点は「家族の顔の良さ」（0〜100）＋「家族の人数」＋「写真全体の良し悪し」−「他人(減点)」です。

| 項目 | 既定 | 何に効くか |
|---|---|---|
| `sharpness` | `0.35` | 家族の顔がボケていない |
| `frontal` | `0.25` | 家族の顔が正面を向いている |
| `eyes` | `0.20` | 家族が目を開けている |
| `smile` | `0.20` | 家族が笑っている |
| `member_bonus` | `20` | はっきり写った家族1人ごとの加点（1人目から。人物の重みを掛けます） |
| `stranger_penalty` | `30` | 他人(減点)の顔1つぶんの減点（GUI で顔認証外にした顔のうち、減点の印を付けた顔だけ。家族の顔より小さいほど軽くなります） |
| `technical` | `0.3` | 写真の画質（ぶれ・ピンぼけ・暗さ） |
| `aesthetic` | `0.1` | 写真の美しさ（構図） |
| `highlights` | `0` | 白飛びの減点 |
| `shadows` | `0` | 黒つぶれの減点 |
| `cutoff` | `0` | 家族の顔が写真の縁で切れているときの減点 |

- 顔の4つ（`sharpness`・`frontal`・`eyes`・`smile`）は、家族の顔1つの良さ（0〜100）の配分です。足して 1 にしておくと、顔の点が 0〜100 に収まります
- 写真全体の5つ（`technical` から `cutoff`）は、`photoarchive assess` で測った写真にだけ効きます。測っていない写真と動画は、画質・美しさを真ん中、欠点を 0 とみなします。それぞれ 100 × 重み まで足し引きします
- 人物ごとの重み（家族の中で誰を重く見るか）と親しい人は、ルールではなく GUI の人物の編集で付けます
- 式と目盛りは仕様書 §9.2 にあります

### 書き方を誤ったとき

**`select` は、写真を測り始める前に止まります**（GUI はルールを読めないと伝えて既定で開きます）。

| 誤り | どうなるか |
|---|---|
| 真偽のキーに `"false"`（引用符付き）や `0` を書いた | 止まります。`true` か `false` で書いてください（文字列の `"false"` は真として扱われ、黙って逆の結果になるため） |
| 数のキーに負の数・文字列・`.nan` を書いた | 止まります |
| `weights` に知らない項目を書いた（綴りの誤りなど） | 止まり、書ける項目を示します |
| `count_per_year` の年が4桁でない・`2027+` が2つある・枚数が負 | 止まります |
| **上の表に無いキーを書いた** | **読み飛ばします**（止まりません。綴りを誤ったキーは効かないので注意してください） |

### GUI の「ルールを保存」

写真の選定タブの「ルールを保存」は、画面の設定を `rule_path` のファイルに書き戻します。

- もとのファイルは同じ場所に `rule.yml.bak` として控えます
- **ファイル内のコメントは消えます**
- `weights` は全部の項目を書きます。`count_per_year` は年の表のとおりの年ごとの対応になります（年の表に行が無いときだけ、もとの値のまま）
- 画面に出していないキー（`date` など）は、もとのファイルの値のまま残ります

## 3. 公開しない語 `config/private_terms.yml`

**開発するとき（コミットするとき）だけ要ります。** アプリは読みません。
このリポジトリは公開されているので、家族の名前・写真の置き場所のパスなどを書かないよう、コミットの前に検査します（#77）。
有効にする手順は README の「公開しない情報」にあります。

```yaml
terms:
  - {text: "山田太郎", replace: "${PERSON_1}"}
  - {text: "taro", replace: "person1", ignore_case: true}
```

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `terms` | 配列 | なし | 公開しない語の一覧 |
| `terms[].text` | 文字列 | （必須） | 公開しない語。文書・コード・ファイル名・コミットメッセージに出てきたら止めます |
| `terms[].replace` | 文字列 | （必須） | 置き換える変数。`python scripts/check_private_terms.py --fix` がこれに置き換えます |
| `terms[].ignore_case` | 真偽 | `false` | 大文字と小文字を区別しない（ローマ字の名前など） |

変数の決まり（`${PERSON_1}` は家族、`person1` はローマ字の名前など）は、サンプルの先頭のコメントと [../README.md](../README.md) の「文書の中の `${...}`」にあります。
