## 踏んだ落とし穴

- **`pgrep -f <名前>` で終わりを待つと、待っているシェル自身のコマンド行に名前が入っていて、永久に「動いている」と判定する。** IQA の試験は 21:43 に止まっていたのに、1時間近く「測定中」と報告し続けた。**`ps -eo pid,cmd | grep "[p]ython -I measure_iqa"` のように、実際のプロセスのコマンド行で見る**
- **`check_private_terms.py ... | tail -1 && gh issue create` は、検査で引っかかっても起票まで進む**（`tail` が成功するため）。#98 の本文にアカウント名入りの URL を一度書いてしまった。**検査はパイプでつながず、終了コードで止める**
- **`check_private_terms.py` の `--message` はファイルのパスを受ける**（中身の文字列を渡すと「ファイル名が長すぎる」で落ちる）
- 写しを比べる段で、進み具合を `(0, 0)` で知らせると、表示が毎回「100% (0/0)」で終わった段とみなして行を積み上げる。総数の分からない段は `total=None`（PR #99 で直した）
- `select` の並べ直しが遅かった原因は、撮影日時・見た目の値・撮影時期の読み直しだった（`lru_cache` で 1.8 → 1.0 秒・PR #108）
- 一時置き場（`$CLAUDE_JOB_DIR/tmp`）に**前のセッションからの DB の複製が残っている**: `replay.db`（519MB）・`proof.db`（423MB）・`idx.db`（383MB）・`gui.db` / `real-v2.db`（各 376MB）・`real.db`（34MB）・`demo.db` / `demo2.db`。消していない。このセッションで作った複製は消した。IQA の仮想環境（`iqa/venv` 2.4GB）も一時置き場にある
