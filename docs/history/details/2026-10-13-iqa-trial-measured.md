# 写真の良し悪しモデル（IQA）の試験（2026-10-13〜15・#105）

NIMA・MUSIQ・TOPIQ（NR）の3つを 200 枚で測った。TOPIQ（IAA）を読み込むところでプロセスがエラーを残さず止まり（2026-10-13 21:43 ごろ。原因は未調査）、CLIP-IQA は測っていない。
**2026-10-15 に上位と下位の写真を利用者に見せ、MUSIQ と NIMA の両方を採ることに決まった**（下の「決定」）。TOPIQ IAA と CLIP-IQA は測り直していない（利用者が先に測ることを選ばなかった）。

## 環境

- **この PC（i7-3770K・AVX2 なし・GPU は使えない）で PyTorch 2.14（CPU 版）は動く。** `torch.backends.cpu.get_cpu_capability()` は `DEFAULT`。pyiqa は 0.1.16
- 作業用の仮想環境はリポジトリの外に作った（2.4GB）。作り直し方:
  ```bash
  python3 -m venv <外>/venv
  <外>/venv/bin/pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
  <外>/venv/bin/pip install pyiqa
  ```
- 学習済みの重みは初回に Hugging Face（`chaofengc/IQA-PyTorch-Weights`）から `~/.cache/torch/hub/pyiqa/` に落ちる。NIMA（208MB）・MUSIQ・TOPIQ（NR）の重みはここに残っている
- 「NNPACK を初期化できない（Unsupported hardware）」という警告が大量に出るが、測定は進む

## 測り方

- 家族の写った写真（手本か自動割り当ての顔がある画像）から 200 枚を無作為に選んだ（`random.Random(0)`）。実データの DB は読み取り専用
- 元写真は NFS から読み、**長辺 1024px に縮小デコード**してからモデルに渡した（`draft` → `exif_transpose` → `thumbnail`）。読み込みは 1 枚 0.17 秒
- モデルごとに、200 枚の点・1 枚あたりの時間・同じ写真を2回測ったときの揺れを出した
- 結果（写真の ID ごとの点）・ログ・見比べ画像（`sheets/`）は **`data/iqa-trial-2026-10-13/`**（git 管理外・この PC の中だけ。家族の写真なので置かない）
- スクリプトは **`scripts/measure_iqa.py`**（2026-10-15 にリポジトリへ入れた）。上の仮想環境の Python で `-I` を付けて流す（`--db data/photoarchive.db --out <外>`）。`--models` で一部だけ測り直せ、`--sheets-only` で見比べ画像だけを作る
- **入れるときに写真の選び方を直した**: 試したときの版は、写真の ID を `ORDER BY` なしで引いてから混ぜていた（SQLite の返す順に依存し、同じ seed でも同じ 200 枚になる保証が無い）。いまの版は ID の順に並べてから混ぜる。**実データでは、古い版と同じ 200 枚になることを確かめた**（2026-10-15。SQLite が索引の順に返していたため。DB の顔が増えれば母数が変わるので、別の写真になる）

## 結果（200 枚）

| モデル | 1 枚あたり（CPU 8 スレッド） | 1.6 万枚の見込み | 点の範囲（最小 / 中央 / 最大） | 揺れ |
|---|---|---|---|---|
| NIMA（美しさ・AVA で学習） | 0.50 秒 | 約 2.2 時間 | 3.56 / 4.70 / 5.86 | 0 |
| MUSIQ（技術的な画質・KonIQ） | 1.53 秒 | 約 6.8 時間 | 18.8 / 69.3 / 78.3 | 0 |
| TOPIQ NR（技術的な画質・KonIQ） | 2.88 秒 | 約 12.8 時間（**一晩に収まらない**） | 0.14 / 0.55 / 0.79 | 0 |
| TOPIQ IAA（美しさ） | — | — | 読み込みで止まった | — |
| CLIP-IQA | — | — | 未測定 | — |

見込みはモデルの時間だけ。NFS の読み込み（1.6 万枚 × 0.17 秒 ≒ 45 分）が別にかかる。

**モデルどうしの一致**（順位の相関・Spearman）:

| | NIMA | MUSIQ | TOPIQ NR |
|---|---|---|---|
| NIMA | — | 0.64 | 0.66 |
| MUSIQ | | — | **0.90** |

上位 20 枚の重なり: MUSIQ と TOPIQ NR は 13 枚、NIMA と MUSIQ は 6 枚、NIMA と TOPIQ NR は 7 枚。
**MUSIQ と TOPIQ NR（どちらも技術的な画質・同じデータで学習）はほぼ同じ順位**を付け、**NIMA（美しさ）は別のものを見ている。** 一晩の上限（利用者の決定）では TOPIQ NR は外れ、技術的な画質は MUSIQ で足りる見込み。

## 上位と下位を見比べて分かったこと（2026-10-15）

モデルごとの上位 15 枚・下位 15 枚と、NIMA と MUSIQ の順位が食い違った写真（それぞれ 10 枚）を並べて見た。

- **MUSIQ の下位はほぼ全部が失敗写真**（手ぶれ・被写体ぶれ・ピンぼけ・暗い）。上位は顔のはっきりした写真。「写りの悪い写真を落とす」役にそのまま使える。新しいカメラ・スマホの写真を高く付ける傾向が少しある
- **NIMA の上位は写真館・舞台・式場など、構図の整った写真**。家族が小さく写った引きの写真（舞台の全景など）も上に付ける。**寄りで撮った赤ちゃんのスナップを下位に落とす**（鮮明な写真でも）。家族写真の選定とは向きがずれる場面がある
- NIMA が上・MUSIQ が下の写真は、暗い舞台・夜の行列・散らかった室内の引き。MUSIQ が上・NIMA が下の写真は、鮮明な寄りの顔・普段の食卓
- TOPIQ NR は MUSIQ とほぼ同じ順位（相関 0.90）で、一晩に収まらないので外した

## 決定（2026-10-15・利用者）

**MUSIQ と NIMA の両方を採る。** 画質（MUSIQ）と美しさ（NIMA）を別々の重みで持ち、GUI で動かす（NIMA の重みは 0 にもできる）。
1.6 万枚の初回はモデルだけで約 9 時間（MUSIQ 6.8 + NIMA 2.2）、NFS の読み込み（約 45 分・2つのモデルで1回読めば足りる）を足して約 10 時間で、**一晩の上限（利用者の決定）ぎりぎり**。#106 では、測った値を DB に残して差分だけ測る・途中で止めても続きから測れる形にする。
