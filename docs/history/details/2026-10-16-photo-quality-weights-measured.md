# 写真全体の良し悪しの既定の重み — 実データの複製で測った（2026-10-15〜16・#106）

**決まったこと（2026-10-16・利用者）: 画質（MUSIQ）0.3・美しさ（NIMA）0.1。白飛び・黒つぶれ・見切れは 0。**
重みはルールの `weights` と GUI の「写真の選定」タブで変えられる。

## 測り方

- 実データの DB を `sqlite3 -readonly ... ".backup"` で複製し、`photoarchive migrate`（版 11）→ `photoarchive assess` を複製に流した。
  **実データの DB には書いていない。** 元写真は NFS から読むだけ
- `select` の比べ方: 利用者の `config/rule.yml`（家族だけ・年 30 枚・2000〜2025 年）で `selection.prepare` を一度呼び、
  `choose` を重みを変えて呼んだ。基準は写真全体の重みが 0 の出力（#106 の前と同じ 638 枚）
- 入れ替わった写真（外れた・入った）を EXIF のサムネイルで並べて目で見た。スクリプトと見比べ画像は
  `data/iqa-weights-2026-10-16/`（git 管理外・家族の写真なので置かない）

## assess の実測

| | |
|---|---|
| 対象（家族の写った画像） | 16,330 枚（試しに先に測った 30 枚を含む） |
| 時間 | 16,300 枚で 5 時間 45 分（**1 枚 1.27 秒**） |
| 読めなかった写真 | 0 枚 |

途中で前処理が遅いと分かって直した（3次補間を行列の積で書いていた。この PC の numpy の BLAS では 1 段 約 2 秒・1 枚 約 10 秒）。
1画素に効く4画素を取り出す形にして 0.09 秒。直したあとも pyiqa と一致することを `scripts/export_iqa_onnx.py` で確かめた（30 枚・差の最大 0.0001・順位の相関 1.0）。

**白飛び・黒つぶれは「明るさの割合」では欠点と見分けられない**（写真館の白背景・暗い室内の明かり）。見切れも自撮りと混ざる。
どれも既定は 0 にし、GUI で動かせるだけにした。

## 気づいたこと

- **動画は `assess` の対象外**で、画質・美しさは真ん中（0.5）とみなす。測った写真の多く（画質の中央 0.83）より低いので、
  既定の重みでは動画が少し下がる（B で 2 本外れた）。動画を測るかは決めていない
- `match` が書く `family_score` も `PhotoQuality` を読む（`select` と同じ点。最初は顔だけにしたが、select と match が同じ点を出すというテストが落ちて気づいた）
- MUSIQ は新しいスマホの写真を高く付ける傾向がある（#105 の記録）。年ごとに枚数を取るので、年をまたいだ偏りにはならない
