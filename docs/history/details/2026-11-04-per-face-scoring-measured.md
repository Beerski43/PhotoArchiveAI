# 顔ごとの点の和と写真全体の点を比重で合わせる — 入れ替わりの測定（2026-11-04・#139）

実データの DB を**読み取り専用**で開き、SQLite の backup でリポジトリの外へ2つ複製した。片方は develop（PR #138 のマージ後）、
もう片方は #139 のコードで、`config/rule.yml` を読んで `select` の候補を用意して選んだ（`selection.prepare` → `choose`。コピーはしない）。
**実データの DB には書いていない**（測った他人(減点)の顔の見え方・表情は複製にだけ書いた）。

DB の状態: 家族の写った写真 18,060 枚・`PhotoQuality` 16,330 枚・他人(減点)の印 3,245 個。

## 結果

出力はどちらも 502 枚（年ごとの枚数はルールのまま）。

| ルール | 入れ替わり | 家族の人数ごとの枚数（1/2/3/4/5 人）develop → #139 | 他人(減点)の顔のある写真 |
|---|---|---|---|
| 利用者の `rule.yml` の重み | **255 枚** | 186/212/73/25/6 → **26**/274/157/39/6 | 15 → 0 |
| 既定の重み（`weights` を書かない） | **157 枚** | 95/243/129/29/6 → **25**/270/163/38/6 | 2 → 0 |

出力の画質（MUSIQ）の中央はどちらも 74 前後 → 73.2 で、ほとんど変わらない。

- **1人だけ写った写真がほぼ出なくなった。** 家族の加点が顔ごとの点の和になったので、2人写っていれば1人の写真のおよそ2倍になる
  （利用者の決定「Σ をそのまま足す」どおり）。**当初は `face_ratio` か人物の重みで戻せると書いたが、下の測り直しのとおり足りなかった**
- 利用者の `rule.yml` は `member_bonus: 17`・`stranger_penalty: 6` を書いていて、#139 ではこの2つを読み飛ばす（警告が出る）。
  他人の重みは既定の 1.0 になり、develop の `stranger_penalty: 6`（顔1つ最大 6 点）よりずっと強く引くので、他人(減点)の顔のある写真が
  15 枚 → 0 枚になった
- `technical: 0.4`・`aesthetic: 0.6` などの写真全体の重みは**比として**読まれる（美しさ寄り）。`highlights: 0.05` も比の一部
- 初回の `prepare` は、他人(減点)の顔 3,245 個の見え方と表情を測るので約 3 分かかった（develop は 5 秒）。2回目からは差分だけ

## レビュー後の測り直し（PR #140・同じ複製を使った）

**同じ人物の顔は、いちばん良い顔だけを足す**ようにし（指摘1）、**2人目以降を薄める `extra_person`** を足した（指摘2。どちらも利用者の決定）。

比重だけを動かしたとき（Σ のまま。重複を直す前。出力 502 枚の 1/2/3/4/5 人）。**比重で1人の写真を戻すには 10 前後が要り、そこでは顔の点は1人あたり最大 10 点しかない。**

| `face_ratio` | 上の測定のときの `rule.yml` の重み | 既定の重み |
|---|---|---|
| 70 | 26/274/157/39/6 | 25/270/163/38/6 |
| 50 | 31/275/152/38/6 | 30/271/156/39/6 |
| 30 | 71/265/125/35/6 | 41/278/142/35/6 |
| 10 | 244/184/53/15/6 | 142/248/81/25/6 |
| 0 | 387/90/18/6/1 | 364/112/19/5/2 |

`extra_person` を動かしたとき（重複を直したあと）。**右の入れ替わりは develop の出力との比較。** `rule.yml` は測定の間に利用者が GUI で保存して `face_ratio: 35` になっているので（2026-11-04 17:44）、その値のまま。develop の1人の写真は `rule.yml` の当時の重みで 186 枚、既定の重みで 95 枚。

| `extra_person` | いまの `rule.yml`（比重 35） | 入れ替わり | 既定の重み（比重 70） | 入れ替わり |
|---|---|---|---|---|
| 1.0（Σ のまま） | 53/274/134/35/6 | 222 | 23/271/164/38/6 | 157 |
| 0.75 | 80/279/108/29/6 | 200 | 25/282/154/35/6 | 142 |
| **0.5（既定）** | **128/275/74/20/5** | **183** | **34/305/129/28/6** | **126** |
| 0.4 | 167/260/54/16/5 | 184 | 50/315/107/25/5 | 124 |
| 0.3 | 206/234/47/10/5 | 193 | 75/311/92/19/5 | 127 |
| 0.2 | 247/206/37/9/3 | 206 | 115/296/72/15/4 | 137 |
| 0.0（最良の1人だけ） | 335/136/23/6/2 | 258 | 292/170/28/8/4 | 262 |

- **既定を 0.5 にしたのはこちらの判断。** 「2人目は半分」で意味が読みやすく、いまの `rule.yml` で1人の写真が 128 枚（develop の 186 枚の約 7 割）まで戻り、2〜3人の写真も残る。既定の重み（比重 70）では 34 枚にとどまるので、1人の写真をもっと出したいなら `extra_person` か `face_ratio` を下げる
- 写真そのものは目で見ていない。良し悪しの判断は GUI で利用者が行う
