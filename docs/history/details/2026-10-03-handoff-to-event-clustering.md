## 直前に何が終わったか（#59 / PR #60）

**特徴量が dlib ResNet（128次元・ユークリッド）から ArcFace（512次元・コサイン）に
変わった。** 詳細は
[2026-10-03-reembed-proof.md](2026-10-03-reembed-proof.md)。

| | dlib 0.4（以前） | **ArcFace 0.45（いま）** |
|---|---|---|
| `evaluate` 正解 | 26.9% | **78.6%** |
| `evaluate` 誤り | 2.6% | **0.0%** |
| 他人誤認率（同じ写真のペア） | 0.5〜1.0% | **1.06%** |

**閾値は「他人誤認率」で選ぶ**（同じ写真に写る2つの顔を別人とみなした誤認率）。
**手本どうしのペアで選ぶと、家族5人の中の取り違えしか数えないので誤る**
（当初 0.60 を選んでしまい、PR #60 のレビューで覆した）。仕様書 §8.3 に教訓として残した。

### 踏んではいけない罠（#59 で通った道）

- **`scan --force-rescan` を使わない。** 顔の行を消して作り直すので**手本が消える。**
  特徴量を作り直すのは `photoarchive reembed`
- **`DETECTOR_VERSION` に特徴量の版を内包させない。** 比較は
  `face.detector_version_of` で正規化する（**実データ全件の再検出＝441GB の
  読み直しを避けるため**）
- **照合は同じ `embed_version` の顔だけを見る。** 混ぜると次元が同じモデル同士で
  黙って無意味な距離が出る
- **`monkeypatch.undo()` を `models` マーカーの外で使わない。** conftest の
  フェイクまで巻き戻り、実物の ONNX を読みに行く（`test_fakes_stay_installed.py` が見張る）
- **`scan` と `reembed` で入力の作り方が違う**が、同じ版に同居させている。
  **経路ごとに版を分けないこと**（分けると互いに見えなくなる）。仕様書 §7.6
