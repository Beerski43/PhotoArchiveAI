## 実データを触るときの約束

**`match` を流す前後で控えを取る。** `cp` ではなく `sqlite3 .backup`（WAL を
取り込むため）。控えの一覧と戻し方は `${HOME}/photoarchive-recovery/BACKUPS.md`。

**`match` は決定的なので、控えがあれば後から結果を再現できる。**
2026-10-08 に、利用者が解除した顔がどれだったか分からなくなったとき、
`match` 直前の控えに対して流し直して 1,778 件を特定できた。

**`match` を流すと、GUI で「割り当てを解除」しただけの顔は戻る。**
判断を残すには `この人物ではない`（`FaceRejection`）を使う。

## この作業で踏んだ落とし穴（繰り返さないために）

1. **実データを書き換える前に、戻せる形で控えを取る。** 件数だけでは戻せない。
   10-06 に、利用者が手動解除した 169 件を `match` の流し直しで巻き戻した
2. **日付の判断を SQL と Python に割らない。** 検証クエリで
   `substr(shooting_date,1,10) < birth_date` と書いて、`0000-00-00` の写真を
   誤検出した。判断は `dates.parse_date` と `db.SHOOTING_DATE_SORT_KEY` に
3. **手本を正解に使う測定は、自分の出力を再現しているだけのことがある。**
   手本の大半は `match` の出力を人が確認して昇格させたもの（survivor bias）。
   「年齢の窓は効かない（92.6% のまま）」という結果はこれだった
4. **古い数字を消すとき、根拠のない丸い制約に置き換えない。**
   回帰テストの「10秒以内」がそれだった
5. **全年齢をまとめた距離の統計には意味がない。** 子供の顔は毎年変わる
