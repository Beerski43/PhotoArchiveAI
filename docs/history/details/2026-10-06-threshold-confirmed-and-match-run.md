## 3. 測れた誤りは、2件とも手本の問題だった

| 顔 | ラベル | 誤った相手 | その距離 | **自分の最短** | 実物 |
|---|---|---|---|---|---|
| 7739 | ${PERSON_1}（年齢31） | ${PERSON_4} | 0.451 | **0.676** | **眠っている赤ん坊**。ラベルが誤り |
| 782 | ${PERSON_1}（年齢47） | ${PERSON_4} | 0.467 | **0.676** | 顔の半分しか写っていない極端な横顔 |

- `/mnt/nfs/.../Photo/2009/0912/PC280135.JPG`（face 7739）
- `/mnt/nfs/.../Photo/2026/260327-29${EVENT}/IMG_20260327_142723.jpg`（face 782）

**どちらも「自分の最短」が 0.676。** つまり${PERSON_1}の手本18件のどれにも似ていない。
**閾値をどこに置いても正しい人物には届かない。** 締めれば取りこぼしに変わるだけ。

この2件を手本から外して測り直すと、**0.60 まで誤り 0% になる。**

| 手本 | 0.45 | 0.46 | 0.50 | 0.60 |
|---|---|---|---|---|
| 126件（現状） | 78.6% / 誤 0 | 81.0% / 誤 1 | 84.1% / 誤 2 | 88.9% / 誤 2 |
| 125件（7739 を外す） | 80.0% / 誤 0 | 82.4% / 誤 0 | 85.6% / 誤 1 | 90.4% / 誤 1 |
| 124件（782 も外す） | 81.5% / 誤 0 | 83.9% / 誤 0 | 87.1% / 誤 0 | 91.9% / 誤 0 |

### それでも閾値は緩めない

**「2件を外せば 0.60 まで誤り 0%」は、閾値を緩める根拠にならない。**
外したのは手本であると同時に**評価の対象**でもあり、いちばん難しい2件を
母集団から抜いた数字だから。仕様書 §8.5 が書いているとおり、この測定は
もともと「人が判別できた顔」に偏っていて甘い側に出る。**そこからさらに
難しい側を抜いた数字で閾値を決めるのは、二重に甘い。**

実運用の候補 57,770 件には、782 のような極端な横顔や部分的な顔が大量に含まれる。
緩めればそれらが「いちばん近い人」に吸われる。**迷ったら厳しい側**（§手順4の判断基準）。

## 7. 測り直す手順

```bash
cd ${REPO_DIR} && source .venv/bin/activate
photoarchive evaluate --db data/photoarchive.db                      # 既定の刻み
photoarchive evaluate --db data/photoarchive.db --thresholds 0.44,0.45,0.46,0.47
photoarchive evaluate --db data/photoarchive.db --margin 0.04        # マージンを振る
```

**誤りになった顔はパスつきで名指しされる**（この Issue で足した）。
「自分の最短」が閾値よりずっと大きければ、閾値ではなく手本の問題。
