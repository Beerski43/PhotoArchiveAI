# 顔候補の自動推薦を GUI に入れた（2026-10-10・#69）

**人物を選び、種別を `未割当` にすると、未割当の顔がその人物に似た順に並ぶ。**
設計は Issue #69 の方針コメント、仕様は仕様書の「人物に似た順」。

## 実データでの1ページ目（受け入れ条件1・2）

実データ（`data/photoarchive.db`）を**読み取り専用で**開き、GUI と同じ条件
（未割当・誕生前を外す・「この人物ではない」を外す）で並べ、1ページ目（200件）の
サムネイルを1枚の画像に並べて目で見た。2026-10-10。

| 人物 | 候補 | 根拠にした手本 | 初回の計算 | 2回目 | 200位の距離 | 目で見た1ページ目 |
|---|---|---|---|---|---|---|
| ${PERSON_1} | 36,460 | 2,705 | 3.6秒 | 0.21秒 | 0.614 | ほぼ全部が同じ大人の男性。横顔・暗い写真が多い |
| ${PERSON_2} | 36,460 | 3,362 | 4.3秒 | 0.20秒 | 0.405 | **上位30件ほどは揃う。** それより後ろは子ども・手・おもちゃ・顔でないものが多い |
| ${PERSON_3} | 32,660 | 1,150 | 1.9秒 | 0.20秒 | 0.313 | ほぼ全部が幼い男の子（大人の顔が3件ほど） |
| ${PERSON_4} | 28,358 | 3,004 | 3.1秒 | 0.21秒 | 0.304 | **先頭27件は同じ行事の同じ女の子。** それより後ろは赤ちゃん・横倒しの顔・顔でないものが混ざる |
| ${PERSON_5} | 20,204 | **142** | 0.6秒 | 0.20秒 | 0.292 | **全部が同じ幼い男の子。** 手本が少なくても落ちない |

**「本人か」は数えきれなかった。** 兄弟の幼いころの顔は互いによく似ていて、96px の
サムネイルでは${PERSON_3}と${PERSON_5}を見分けられない。数えたのは「別人と分かるもの」まで。
**本人の数を記録するのは、利用者が GUI で割り当てた件数で代える。**

「2回目」は同じ人物で並べ直したときの時間（ページ送り・絞り込みの変更）。
**計算し直さず、id の読み直しと並べ替えだけ**になっている。

### 候補の側の「整列できない顔」

1ページ目の顔の見え方を `appearance.measure_thumbnail` で測った（DB には書いていない）。

| 人物 | 1〜30位 | 1〜200位 | 201〜600位 |
|---|---|---|---|
| ${PERSON_1} | 9 | 91 | 70 / 400 |
| ${PERSON_2} | 4 | **140** | 382 / 400 |
| ${PERSON_3} | 1 | 12 | 27 / 400 |
| ${PERSON_4} | 0 | 78 | 189 / 400 |
| ${PERSON_5} | 0 | 0 | 0 / 400 |

**${PERSON_2}と${PERSON_4}の1ページ目の後ろ半分は、整列できない顔が埋めている。** 手本の側は
整列できないものを外してあるが、候補の側は測っていない（未割当 3.6万件を測ると
約10分）。**ただし${PERSON_1}の 91 件は、目で見ると本人の横顔が多い**（横顔は5点が取れない）。
整列できない顔を後ろへ回すと、これも一緒に後ろへ行く。

**利用者が「測らずに入れる」と決めた**（2026-10-10）。上位30件はどの人物でも揃って
いて、混ざったものは `誰でもない顔として除外…` で外せばデータの掃除にもなる。

${PERSON_2}の1ページ目が荒れるのは、**未割当に残っている${PERSON_2}の顔が少ない**せいでもある
（整列できる顔だけで並べても 200位の距離は 0.449。`match` の閾値 0.45 の外）。

## 測り直す手順

```bash
cd ${REPO_DIR} && source .venv/bin/activate
python - <<'EOF'
import sqlite3, time
from photoarchive_ai import db, recommend
c = sqlite3.connect("file:data/photoarchive.db?mode=ro", uri=True); c.row_factory = sqlite3.Row
for p in db.list_persons(c):
    ids = db.face_ids(c, unassigned=True, born_by=p["birth_date"], not_rejected_for_person=p["id"])
    sim = recommend.PersonSimilarity(p["id"]); t = time.time(); n = sim.update(c, ids)
    page = recommend.rank(ids, sim.distances)[:200]
    print(p["name"], len(ids), n, f"{time.time()-t:.1f}s", page[:10])
EOF
```

1ページ目を目で見るには、`db.faces_by_ids(c, page, with_thumbnail=True)` のサムネイルを
並べた画像を作る（使い捨て。2026-10-10 は 20列×10行・1枚 96px）。

## 並びの逆向き（Issue #69 のコメント）

「高い順という選択があるなら低い順もあるべき」。すべての並びに逆向きを足した。
**値を持たない顔はどちらの向きでも最後。**

実データの未割当 36,458 件で1ページ目を読む時間（2026-10-10）:

| 並び | 時間 |
|---|---|
| 撮影日時の新しい順（既定） | 9ms |
| 撮影日時の古い順 | 537ms |
| 画質の低い順 | 524ms |
| 確信度の高い順 | 112ms |

古い順は「撮影日時の無い顔を最後」にするため索引を使えず、毎回並べ替える。
既定の並びではないので許した（`db._shooting_date_query`）。

## レビュー対応: 未計測の手本を使う前に測る（PR #71 指摘1）

GUI で割り当てたばかりの手本は見え方が未計測で、整列できなくても根拠に入っていた。
`match` と同じ `matcher.teacher_usable` を通して、使う前に測るようにした（値は DB に残す）。

実データの複製（${PERSON_4}・種別「未割当」・2026-10-10）での時間。

| 操作 | 修正前 | 修正後 |
|---|---|---|
| 初回 | 3.16秒 | 3.32秒 |
| ページ送り | 0.48秒 | 0.61秒 |
| 1件割り当てたあとの並べ直し | 0.83秒 | 1回目 1.63秒・2回目以降 0.96〜0.98秒 |

- 増えたぶんの大半は、未計測の手本を探す問い合わせ（`db.faces_without_appearance`。
  `Face` を全件たどる。実データで 112ms）
- 割り当て直後の1回目だけ長いのは、FaceMesh を初めて読み込むため
- `match` を流したあとの実データでは、未計測の手本は 0 件だった
