# 顔候補の自動推薦を ArcFace で測り直した（2026-10-08）

**結論: 成り立つ。** 2026-09-20 に dlib で「作らない」と決めたが、その根拠は消えた。

## 何を測ったか

手本を1件抜き、**未割当 30,835 件の中に混ぜて**、その人物の残りの手本から
距離の近い順に並べたとき、抜いた顔が何番目に出るか。手本 300 件を無作為抽出。

**同じ写真に写る同一人物の手本は外す**（連写が残ると必ず1番になり、数字が甘くなる）。

## 何が変わったのか

2026-09-20 の測定は **dlib の 1位正解率 64〜70%** が前提だった。
ArcFace は **95.2%**、行事をまたぐ分離は **+0.033 → +0.418（12.7倍）**。
[モデルの比較](2026-10-02-embedding-model-comparison.md)。

**ROADMAP にはこの測り直しが宿題として書いてあった。**

> ⚠️ この結論は dlib での測定。1位正解率が 64〜70% だったことが前提なので、
> **ArcFace（95.2%）に替えたら測り直す。**
> **差し替え前の数字で「作らない」と決め続けないこと。**

**その警告どおりになった。**

## GUI にとって何を意味するか

いまの未割当の一覧は**撮影日時の新しい順**で 30,835 件。人物を決めて割り当てるには、
その人物が写っている顔を目で探すことになる。

**「この人物に似た順」に並べられれば、1ページ目でほぼ片付く**（94.0%）。
**手作業の量そのものを落とせる、いちばん大きい一手。**

## 測り直す手順

```bash
cd ${REPO_DIR} && source .venv/bin/activate
# 測定スクリプトは使い捨て。手順はこの文書のとおり:
#   1. db.load_manual_faces で手本を読む
#   2. db.iter_unassigned_embeddings で未割当を読む
#   3. 手本を1件抜き、同じ写真の同一人物も外し、残りの手本との最小距離で
#      未割当を並べ、抜いた顔の順位を数える
```

**約 10 分かかる**（手本 10,577 × 未割当 30,835 の距離を300回）。

## 注意

**この測定も手本を正解として使っている。** 手本は「人が見て分かった顔」に偏って
いるうえ、**自動割り当てを人が確認して作った集合**なので、`match` が間違えた顔は
手本から外れている（survivor bias）。**実運用の順位はここで出る数字より悪くなる。**
**方向は必ずこちら側**なので、「1ページ目に 94%」は上振れと読むこと。
