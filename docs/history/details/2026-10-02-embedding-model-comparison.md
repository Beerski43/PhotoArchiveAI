## 2. 読み取れたこと

### (1) 整列が効く。モデルを替えるだけでは足りない

**(c) 78.6% 対 (d) 95.2%。整列だけで +16.6pt。**

ArcFace は 112×112 のテンプレートに5点（両目・鼻・両口角）を合わせる前提で
学習されている。縮めて渡すだけ（c）では、現行の dlib をサムネイルから作り直した
もの（b, 82.5%）**に負ける**。

**「モデルを新しくすれば上がる」ではなく、「新しいモデルの前処理の規約に
合わせれば上がる」。** 測らずに (c) だけ試して「ArcFace でも大差ない」と
結論づける筋があったので、(c)(d) を両方測ったのは正しかった。

5点は **MediaPipe FaceMesh** から取っている（`scoring.py` が既に依存しているので
**新しい依存は増えていない**）。5点が取れなかった顔は 126 件中 **14 件**で、
縮小して通した（捨てると (c) と母集団が変わって比べられなくなる）。

### (2) サムネイルからの作り直しは、代償どころか改善だった

**(a) 69.8% 対 (b) 82.5%。同じ dlib なのに、サムネイル由来のほうが +12.7pt 高い。**

**これは解像度の話ではなく、切り出し方の話。** 両者の違いはこう。

| | 入力の矩形 |
|---|---|
| (a) 原寸経路（現行の `scan`） | 検出矩形を正方形化し、**原寸画像の中で 25% 広げる** |
| (b) サムネイル経路 | サムネイル（検出矩形の生クロップ）に `face_rect` をかけるが、**画像の端で切れるので実質ほぼ密着** |

つまり **(b) のほうが顔に密着している。** `face.EMBED_PADDING = 0.25` の
コメントは「0.0〜0.25 はほぼ同等」と書いているが、**この測定では密着側が明確に
良い。**

- **サムネイル（短辺の中央 160px）の解像度は足りている。** ArcFace の入力は
  112×112 で、112px 未満のサムネイルは 7.3% しかない
- **元写真を読み直す必要は無い。** これが所要時間を 10 時間から 142 分へ落とした
  いちばんの理由

> **ただし (a) 対 (b) は「解像度」と「切り出し方」の2つを同時に動かしている。**
> どちらがどれだけ効いたかは分けて測っていない。**「サムネイルで十分」という
> 結論には足りるが、「`EMBED_PADDING` を下げるべき」の根拠にはまだ足りない。**

### (3) 「dlib は頭打ち」は、行事をまたぐ照合に限った話だった

9/20 に「同一 0.57 / 別人 0.61 でほぼ重なっている」と測り、**実装の欠陥ではなく
モデルの限界**と結論づけた。それは正しいが、**プールした平均を見ていた。**

行事の中と外で分けると (a) でも **+0.156 対 +0.033** で、**行事の中なら 4.7 倍**
分離している。dlib が効かないのは「22年分の加齢と照明をまたいだ単一空間での
全体照合」であって、**同じ日・同じ場所の顔を束ねる用途なら今のモデルでも使える。**

**(d) はその両方を押し上げた。** 行事をまたぐ差が +0.418 まで開いたので、
**これまで不可能としていた「行事をまたぐ自動紐づけ」が射程に入る**
（閾値 0.830 で同一を 88% 拾い、別人の誤りは 11%）。

### (4) 所要時間

| # | 1件あたり | 顔 58,606 件 |
|---|---|---|
| (b) dlib / サムネイル | 129.5ms | 126分 |
| (c) ArcFace / 整列なし | 122.9ms | 120分 |

さらに縮む**が、142分は一度きりなので急がない。

## 3. 測定の限界（割り引いて読むところ）

- **手本が126件しかない。** 1位正解率の誤差は ±8pt 程度ある。
  95.2% と 82.5% の差（12.7pt）は基準の +15pt を単独では満たさないが、
  **(a) との差は +25.4pt** で基準を満たす
- **行事の中・別人のペアが n=49 しかない。** 「行事の中」の数字はいちばん
  揺れやすい
- **5人の家族しか入っていない。** 他人を含めた誤一致率は測れていない
  （`evaluate` が測るのはそちら）
- (a) 対 (b) が2要因を同時に動かしていること（上記）
- **束ねの純度は測っていない。** 「1つの束に2人が混ざる率」は次の子Issueで測る

## 4. 次にやること

**採用が決まったので、別の子Issueで本体に入れる。** この Issue では本体を触らない。

1. **次元数と距離尺度をモデルの属性にする**
   - `db.EMBEDDING_DIM = 128` → 512（`db.py:34`）
   - `matcher.DEFAULT_THRESHOLD = 0.4` / `DEFAULT_MARGIN = 0.05`（`matcher.py:28-29`）と
     `scoring.distance_to_similarity`（`scoring.py:51`、`SIMILARITY_REFERENCE_DISTANCE = 0.6`）に
     **dlib のユークリッド尺度が埋まっている**
2. **`reembed` サブコマンドを足す**
   - サムネイルから `embedding` と `embed_version` だけを書く
   - **割り当て（`person_id` / `assign_source` / `age`）に触らない。**
     `scan --force-rescan` は手本を巻き添えにするので**使わない**
   - 手本 126 件と除外 268 件は、特徴量を作り直しても**そのまま残る**
     （人物との紐づけは `embedding` とは別の列）
3. **`DETECTOR_VERSION` を `EMBED_VERSION` から切り離す**
   - いま `DETECTOR_VERSION = f"mediapipe_fd1/{EMBED_VERSION}"`（`face.py:74`）と
     連結されており、**特徴量だけ替えても検出のやり直し対象になる**
   - 検出結果（矩形・サムネイル）は作り直す必要が無い
4. **5点整列を `face.py` に入れる。** 整列が +16.6pt を持っているので、
   ここを省くと採用した意味が半分消える
5. 作り直したあとで `evaluate` を回し、**閾値を再確定する**（Phase 3 手順5）

## 5. モデルの出どころ

`models/w600k_r50.onnx`（174MB）。InsightFace の `buffalo_l` パックから
認識用の1本だけを取り出したもの。

```
sha256  4c06341c33c2ca1f86781dab0e829f88ad5b64be9fba56e56bc9ebdefc619e43
```

**`insightface` パッケージは入れていない**（モデル動物園と GPU 版 onnxruntime を
引き込むため）。`onnxruntime` だけを足し、前処理は InsightFace の `ArcFaceONNX` と
同じにした（入力 RGB・`(x - 127.5) / 127.5`・NCHW）。取得手順は README にある。
