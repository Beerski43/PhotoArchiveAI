## 測って分かったこと（いちばん大事な部分）

**`photoarchive evaluate` を実データで流した結果。**

```
閾値 0.40 →  正解 26.9% / 取りこぼし 70.5% / 誤り 2.6%
閾値 0.55 →  正解 33.3% / 取りこぼし 61.5% / 誤り 5.1%
```

### 1位正解率が 64〜70%。これが閾値の上限

| 測ったもの | 値 |
|---|---|
| 1位が正解の率（閾値・マージンを無視した上限） | **64.1%**（評価対象78件）/ **69.8%**（手本126件で再計算） |
| 同一人物どうしの距離（中央、同じ写真は除く） | **0.57** |
| 別人どうしの距離（中央） | **0.61** |

**分布がほぼ重なっている。** 閾値をどう動かしても、この上限は超えられない。

**実装の欠陥ではない**（ここは確認済みなので、やり直さなくてよい）。

- 顔は十分大きい（短辺の中央 300px、手本 690px）。80px 未満は 2.4% だけ
- 色順は正しい（`PIL.convert("RGB")` / 動画は `BGR2RGB`）
- 5点ランドマークでの整列は効いている
- 年齢差0の同一人物でも距離 0.56 → 加齢だけが原因でもない
- 家族5人（うち子ども3人が 0〜17歳）という対象が、dlib の2017年モデルに厳しい

### 顔候補の自動推薦は「効かない」と測れた

手本を1件抜き、未割当 58,273 件の中で何番目に出るかを測った。

```
          1位   上位10  上位50  上位200   中央順位
全体       3%      3%      3%      4%     9,769 番目
（撮影日時順なら平均 29,136 番目なので、3倍マシになるだけ）
```

**仕様書 §10.7 の「顔候補の自動推薦」は、この特徴量のままでは作っても使えない。**
作る前に測れた。**同じ結論を出すために再測定しないこと。**

### dlib の使い方には伸びしろがあった（未着手）

同じ126件を実写真から作り直して比較した。

| 設定 | 1位正解 | 同一(中央) | 別人(中央) | 差 |
|---|---|---|---|---|
| `sp5 / jitter 0`（**いまの設定**） | 69.8% | 0.56 | 0.61 | 0.05 |
| **`sp5 / jitter 10`** | **75.4%** | 0.51 | 0.57 | 0.06 |
| `sp68 / jitter 0` | 69.0% | 0.57 | 0.60 | 0.03 |
| `sp68 / jitter 10` | 69.8% | 0.52 | 0.56 | 0.04 |

- **`face.compute_embedding` の `compute_face_descriptor(image, shape, 0)` の
  第3引数がジッタ回数。** いま 0 で、dlib の精度を出しきっていない
- 10 にすると +5.6 ポイント。**ただし「差」は 0.05 → 0.06 にしかならない**ので、
  dlib では 75% 前後が頭打ち
- 68点ランドマークは効かない（5点のままでよい）
- 入れる場合の代償: 特徴量の計算が 0.5h → 4.9h、＋写真の読み直し 5.1h（NFS）、
  `EMBED_VERSION` を上げて全件再スキャン

## 決まった方針

**#18（GUI改善）を前倒しで着手する。「判断の数を減らす」方向。**
ユーザーの選択（2026-09-20）。

測定が支持している候補。**モデルを替えても残る効き目**である点が理由。

| 候補 | 測定した根拠 |
|---|---|
| **フォルダ単位の一括除外** | 上位100フォルダで **51.5%**（30,094件）。最大は結婚式1,357件・学校行事987件で、ほぼ他人 |
| **1枚1顔をまとめて処理** | **21,961枚（38%）は写っている顔が1つだけ** |
| **キーボードで割り当て** | 自動化が効かない以上、1件あたりの手数がそのまま総時間 |
| ~~顔候補の推薦~~ | **作らない。** 効かないと測れた（上記） |

補足の数字: 未割当はフォルダ 1,040 個に散らばり、平均 56 件／最大 1,357 件。
1枚に2人が 8,990 枚、3人が 2,827 枚。

改めて測り直して判断する。
