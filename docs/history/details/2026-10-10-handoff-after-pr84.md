## 踏んだ落とし穴

- **ワークツリーでテストすると、別の作業ツリーのコードを読む。** `pip install -e .` の参照先は本体の `src/` なので、`git worktree add` した先で `pytest` を流すと**本体のコードをテストしてしまう**。`PYTHONPATH=<ワークツリー>/src` を付ける（PR #81 のレビュー対応で、利用者の `convert-heic` の実行と干渉しないようワークツリーを使ったときに確かめた）
- **端末の出力を Python で読むときは `open(..., newline="")`。** 既定の text モードは単独の `\r` を改行に変えるので、進捗表示の書き直しが壊れて見える（本当は正しかった）
- **`git filter-repo --invert-paths` と `--filename-callback` を併用すると、callback に `None` が来る。** `None` はそのまま返す
- **初版の2コミットに `.venv` が入っていた。** `.pyc` にホームのパスが埋まっており、文字の置き換えでは消せない（バイナリを置き換えると壊れる）。履歴から取り除いた
- **`gh api --paginate --slurp` はこの環境の gh に無い。** ページごとの JSON 配列が続けて出るので、`json.JSONDecoder().raw_decode` で読む
- **`a && b <<EOF ... EOF` のあとに改行して `echo saved` と書くと、`a` が失敗しても saved が出る。** 依頼文の下書きを「保存した」と報告したが、実際には書かれていなかった（引き継ぎのときに気づいて作り直した）。成否は `&&` でつなぐか、ファイルの有無で確かめる
- **PR の番号を先回りして書かない。** #77 へのコメントに「PR #83」と書いたが、#83 は利用者が先に起票した Issue で、PR は #84 だった（直した）
- **実行中の `photoarchive` があってもブランチは切り替えられる**（起動時にコードを読み込み済み）が、関数の中で import するモジュールは例外。切り替える前に `grep` で確かめた
