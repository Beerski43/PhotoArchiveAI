# 人物ごとの重み・親しい人・減点する顔 — 入れ替わりの測定（2026-10-17・#110）

実データの DB を**読み取り専用**で開き、SQLite の backup でリポジトリの外へ複製した（`photoarchive assess` の実行中。`PhotoQuality` は 240 枚ぶんしか埋まっていない）。
同じ複製を2つに分け、片方は develop（PR #111 のマージ後）のまま、もう片方は #110 のコードで `migrate`（版12）してから、`config/rule.yml` で `select` の候補を用意して選んだ（`selection.prepare` → `choose`。コピーはしない）。

## 結果

**減点する顔の印はまだ1つも無い**（除外の顔は 1,565 個）。人物の区分と重みも既定のまま（全員が家族・重み 1.0）なので、差はすべて **#100 の他人の減点が無くなったこと**から来る。

| | develop | #110 |
|---|---|---|
| 出力 | 638 枚 | 638 枚（**入れ替わり 110 枚**） |
| 他人の減点を受けた写真（develop の式で） | 38 枚（重み 1 以上 8 枚） | **145 枚**（重み 1 以上 83 枚） |
| 写っている家族の人数ごとの枚数（1/2/3/4/5 人） | 164/322/120/26/6 | 157/319/129/27/6 |

入ってきた 110 枚は、**すべて** develop の式で他人の重みのある写真だった（76 枚は重み 1 以上 = 家族と同じくらいの大きさの他人）。
#100 で押し出した写真がほぼそのまま戻ってくる。

## 読み方

- これは利用者の決定（#110・「選んだ顔だけ・大きさを掛ける」「#100 の家族らしくなさはやめる」）どおりの動き。**写真に入ってほしくない人の顔を、GUI の除外済みで選んで印を付ける（`P`）まで、他人の減点は効かない**
- 入ってきた写真の他人には、写してよい人（友だち・親戚）と入ってほしくない人が混ざっているはず。どちらなのかは利用者にしか決められない。親しい人として登録して割り当てれば加点になる
- 同じ人が何枚にも写るなら、その人を人物として登録し、区分を「親しい人」にするか、除外して印を付けるかのどちらかにすると、まとめて片付く（印は顔ごと）

## 測り直し

スクリプトはリポジトリに入れていない（`selection.prepare` → `choose` の ID を develop と比べるだけ）。印を付けたあとの効き方は、同じ手順で印のある DB を複製して比べる。
