## #102 で組み直した（2026-10-13・プラン改版）

#88 で並びの式を1つずつ足したが（#95・#98・#100）、利用者は結果に満足していない（「思っていた以上に良くない。根本的に仕組みを考え直したい」）。
**式と重みがコードに固定されていて、利用者が結果を見ながら動かせない**こと、**写真全体の写り（構図・露出・美しさ）を見ていない**ことが原因と見た。

**設計の核**: `select` を「候補を用意する（`selection.prepare`・DB と測定・重い）」と「選ぶ（`selection.choose`・重みで点を出し、並べ、束ね、年ごとに取る・軽い）」に分け、重みと年ごとの枚数をルールの YAML に出す。GUI の「写真の選定」タブは `choose` を何度も呼んで並べ直す。CLI も同じ2段を通る。

## 処理時間と GPU

いまの GPU（GTX 670・Kepler・VRAM 2GB）は CUDA 11 以降で切られていて、`onnxruntime-gpu` も PyTorch の CUDA 版も動かない。
OpenCL（OpenCV DNN）なら動くが、ArcFace で **CPU の onnxruntime より 2〜3 倍遅い**（2026-10-11 に実測。数字は #88）。
**推論は CPU の ONNX Runtime に揃える**（新しい GPU を足したときに #8 で `onnxruntime-gpu` へ差し替えるだけで済むように）。
重いのは 4 の美しさモデルなので、測った値を DB に残して差分だけ測る形にする。
