  フェーズ全部の Issue を先に作らない

  未着手フェーズの詳細は陳腐化するので書かない

## 現在地

**Phase 0 / Phase 1 は Issue #30 で、Phase 2 は Issue #32 で完了。
Phase 3 は Issue #35 で着手中。**

Phase 3（実データでの精度確立）が、この製品の価値をまだ実証していない工程。
全件スキャン → GUI で人物ごとに20〜50枚を割り当て → `match` の**取りこぼし率**を
実測して閾値を確定する。

**全件スキャンは完了した**（2026-09-20。Media 70,297 件／顔 58,606 件）。
**実測の道具（`photoarchive evaluate`）も用意した。** 残るのは
**GUI での手動割り当て（人手）** と、その結果を見ての閾値の確定。
詳細は [phase-3-accuracy.md](phase-3-accuracy.md)。

手動割り当てを楽にするための GUI 改善を、Phase 4 から先行して入れている
（#41・#48・#52 は PR #51 まで、#53 は PR #54 でマージ済み）。
**#55（フォルダ単位の一括除外）は PR #56 を取り下げた。** 束ねる単位が
フォルダから**行事（フォルダ×日）**へ変わるため、下の手順3が引き取る。

**2026-10-02 に方針を転換した。** 2026-09-20 の測定（1位正解率 64〜70% で頭打ち）の
**読み方を1つ間違えていた。**

| 条件（手本126件） | 同一人物の距離(中央) | 別人(中央) | 差 |
|---|---|---|---|
| **同じ行事の中**（同フォルダ・同日） | **0.480** | 0.636 | **+0.156** |
| 行事をまたぐ | 0.578 | 0.611 | +0.033 |

「分布がほぼ重なっている」は**行事をまたぐペアで薄まった平均**だった。
**dlib が効かないのは「22年分の加齢をまたいだ単一空間での全体照合」**であって、
同じ日・同じ場所なら使える信号が残っている（差は 4.7 倍）。

そこで **`match` の作りを「全体照合」から「行事の中で束ねて、時間でつなぐ」へ
変える**（Phase 3 の節を参照）。

**2026-10-04 に、この表を ArcFace で測り直した**（#61 の着手条件。測定は
[../history/details/2026-10-04-event-clustering-measured.md](../history/details/2026-10-04-event-clustering-measured.md)）。

| 条件（手本126件・ArcFace） | 同一人物(中央) | 別人(中央) | 差 |
|---|---|---|---|
| **同じ行事の中** | 0.295 | 0.908 | **+0.613** |
| 行事をまたぐ | 0.533 | 0.951 | +0.418 |

**dlib では 4.7 倍だった差が 1.5 倍まで縮んだ。** 「行事の外は照合できない」という
当初の根拠はもう成り立たない。**それでも行事で束ねる理由は置き換わった** —
平均連結は顔の数の2乗の費用がかかり（未割当 51,860 件を一度に束ねると 21GB）、
同じ日・同じ場所なら**人が目で検算できる**。

**あわせて特徴量モデルの差し替えが決まった**（#57。測定は
[../history/details/2026-10-02-embedding-model-comparison.md](../history/details/2026-10-02-embedding-model-comparison.md)）。
**ArcFace＋5点整列で 1位正解率 69.8% → 95.2%**、行事をまたぐ差は
+0.033 → **+0.418（12.7倍）**。保存済みサムネイルから作り直せるので
**NFS の再読み込みは要らず、全件 約158分**で済む（実測 162ms/件。
[測定](../history/details/2026-10-03-reembed-proof.md)）。

### Phase 3 — 実データでの精度確立（着手中・#35）

詳細は [phase-3-accuracy.md](phase-3-accuracy.md)。

**2026-10-02 に作りを変えた。**

```
いままで:  58,212 件の顔を、126 件の手本と単一空間で照合する（1位正解 64〜70%）
これから:  行事の中で束ねる（容易） → 人がその束にラベルを付ける
           → 隣の行事へ時間で繋ぐ（容易）
```

**機械の仕事を「全体照合（不可能）」から「局所の束ね（容易）」へ移す。**
人間の判断の数は 58,212 から数千へ落ちる。根拠になった測定。

| 測ったもの（2026-09-20 / 2026-10-02） | 値 |
|---|---|
| 未割当が散らばっている行事（フォルダ×日） | **2,685 個**（90.2% が ≥10件の 1,038 個の中） |
| 撮影のあった日 | 1,847 日（2004-04-16〜2026-07-05） |
| **連続する撮影日の間隔** | **中央 2日**（7日以内 88% / 30日以内 99%） |
| 保存済みサムネイル | 短辺の中央 160px・全部で 272MB・112px 未満は 7.3% |
| 誕生日による候補の絞り込み | 平均 4.11/5 人（18%削減） |

**連続する撮影日が中央2日なので、0歳と15歳を直接照合する必要がない。**
隣の行事へ繋ぐのを繰り返せば 22 年を渡れる。

1. ~~全件スキャン~~ **完了**（2026-09-20。Media 70,297 件／顔 58,606 件）
2. ~~特徴量モデルの差し替えを測る~~ **完了**（#57・PR #58。採用が決まった。
   ArcFace＋5点整列で1位正解 69.8% → 95.2%、行事をまたぐ差 +0.033 → +0.418）
   → **本体への差し替えも完了**（#59・PR #60）。
   **実データも ArcFace へ作り直し済み**（2026-10-03。無損失。58,606 件すべて新しい版。
   [記録](../history/details/2026-10-03-handoff-to-event-clustering.md)）。
   **`match` のやり直しは未実施**
3. ~~**行事ごとに束ねてまとめて割り当てる**~~ **実装した**（#61。#55 を引き取った）。
   行事（フォルダ×日）で絞り、平均連結で束ね、束ごとにまとめて割り当て・除外・
   割り直しができる。**連結の上限 0.45 で、人間の決定が 51,860 件 → 19,678 回
   （62.1% 減）**。他人誤認率 0.66%（照合の閾値と同じ数え方）。
   [測定](../history/details/2026-10-04-event-clustering-measured.md)
4. **隣の行事へ時間でつなぐ**（手順3のあとで設計する）
5. **取りこぼし率を実測し、閾値を確定する。** `photoarchive evaluate` が手本を
   1件ずつ抜いて測る（**道具は実装済み**）。**モデルを替えたら閾値も尺度ごと
   変わる**（ArcFace はコサイン距離）
6. `selection.py` の `family_only` の決着。閾値 0.4 で切ると `assign_score` の下限が
   下限を持つため（ArcFace 0.45 では 55.0）、`family_score > 0.0` が「割り当てが1つでもあれば通る」に
   なっている
7. `Person.name` の UNIQUE 制約の要否（入れるなら既存DBの移行が必要）
8. `data/photoarchive.db.bak-pre28`（773MB、#28 の移行前バックアップ）を
   消してよいか判断する

**モデルの差し替えで入れたもの**（#59）。詳細は仕様書 §7.6。

- `embedding.py` に**モデルの記述**（次元数・距離尺度・閾値・版）を1か所へ集めた。
  `db` / `matcher` / `scoring` / `face` はそこを見る
- **`reembed` を足した。** サムネイルから特徴量だけを作り直す。
  **`scan --force-rescan` は使わない**（手本を巻き添えにする）
- **5点整列を入れた**（+16.6pt を持っている）
- `DETECTOR_VERSION` を `EMBED_VERSION` から切り離した。比較は
  `face.detector_version_of` で正規化する（**実データ全件の再検出を避けるため**）
- **照合は同じ版の特徴量だけを見る**（`embed_version`）。`reembed` の途中は
  必ず混在する

### Phase 4 — GUI の作り込み（#18）

**#23（顔登録の削除機能）は #28 と #30 で解消済み。** 「割り当て済みを確認」で
解除・除外・年齢変更（未設定へ戻すことも含む）・自動割り当ての確定ができ、
ページャも入った。

残るのは #18（GUI改善）。**Phase 3 の手順2が詰まって次へ進めないため、
2026-09-20 に前倒しで着手すると決めた。** 実データで測ったうえで、
**「判断の数を減らす」方向**を選んでいる。

| 候補 | 状態 | 測定した根拠（2026-09-20） |
|---|---|---|
| フォルダ単位の一括除外 | **#61 で実装**（行事＝フォルダ×日として） | 上位100フォルダで 51.5%（30,094件）。最大は結婚式1,357件で、ほぼ他人 |
| 1枚1顔をまとめて処理 | **#61 の束ねに吸収**（1枚1顔の写真は、その人物の束に入る） | 21,961枚（38%）は写っている顔が1つだけ |
| キーボードで割り当て | 未着手 | 1件あたりの手数がそのまま総時間 |

**仕様書 §10.7 の「顔候補の自動推薦」は作らない。** 実データで測ったところ、
手本を1件抜いて未割当 58,273 件の中で探させると**中央 9,769 番目**にしか
出なかった（撮影日時順の 29,136 番目に対して3倍マシになるだけ）。
根っこは **1位正解率 64〜70%** で、これが閾値の上限。測定の詳細は
[../history/details/2026-09-20-manual-assignment-measurements.md](../history/details/2026-09-20-manual-assignment-measurements.md)
と Issue #18 のコメント。

**⚠️ この結論は dlib での測定。** 1位正解率が 64〜70% だったことが前提なので、
**ArcFace（95.2%）に替えたら測り直す。** 行事をまたぐ分離が +0.033 → +0.418 へ
12.7倍になっており、**推薦が成り立つ可能性が出てきた。**
測定は [../history/details/2026-10-02-embedding-model-comparison.md](../history/details/2026-10-02-embedding-model-comparison.md)。

**差し替え前の数字で「作らない」と決め続けないこと。**

**2026-10-04 に測り直した**（#61）。1位正解率は 95.2%、行事をまたぐ分離は +0.418 で、
**当時の根拠は消えている。** ただし #61 では推薦を作らず、束ねるところまでにした。
「この束は誰か」を推薦するかは `match` の役割と重なるので、別に判断する
（仕様書 §10.7 に書いた）。

**#41（プレビューに撮影日時とフォルダを出す）は、Phase 3 の途中で先行して実施した。**
手順2（GUI で人物ごとに20〜50枚を割り当て）で年齢を入力できず、止まっていたため。
**#48（人物の誕生日から年齢を計算する）も同じ理由で先行する。**

**#52（GUI の起動時に移行を実行する）は #48 から出た。** #48 がスキーマ版を
上げるため、GUI しか使わない利用者が移行のためだけに端末へ出ることになる。
#48 の `db.missing_columns` に依存するので、**PR #51 で #48 と一緒に出している**
（CLAUDE.md §3 の例外）。
