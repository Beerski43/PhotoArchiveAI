## 使い方

- **新しいフェーズに入るときに Issue を起票し、下の表に番号を書く。**
  フェーズ全部の Issue を先に作らない
- 着手中・着手済みのフェーズだけ `phase-N-*.md` に詳細を書く。
  未着手フェーズの詳細は陳腐化するので書かない
- 1つのフェーズが1つの PR とは限らない。**フェーズは親 Issue、実作業は
  子 Issue** に分け、**1つの子 Issue につきブランチと PR を1本ずつ**作る
  （CLAUDE.md §3）

**手本**だった。**5点整列ができない手本を受け入れの根拠にしない**＋**手本の年齢で閾値に

**2026-10-02 に方針を転換した。** 2026-09-20 の測定（1位正解率 64〜70% で頭打ち）の
**読み方を1つ間違えていた。**

| 条件（手本126件） | 同一人物の距離(中央) | 別人(中央) | 差 |
|---|---|---|---|
| **同じ行事の中**（同フォルダ・同日） | **0.480** | 0.636 | **+0.156** |
| 行事をまたぐ | 0.578 | 0.611 | +0.033 |

「分布がほぼ重なっている」は**行事をまたぐペアで薄まった平均**だった。
**dlib が効かないのは「22年分の加齢をまたいだ単一空間での全体照合」**であって、
同じ日・同じ場所なら使える信号が残っている（差は 4.7 倍）。

そこで **`match` の作りを「全体照合」から「行事の中で束ねて、時間でつなぐ」へ
変える**（Phase 3 の節を参照）。

**2026-10-04 に、この表を ArcFace で測り直した**（#61 の着手条件。測定は
[../history/details/2026-10-04-event-clustering-measured.md](../history/details/2026-10-04-event-clustering-measured.md)）。

| 条件（手本126件・ArcFace） | 同一人物(中央) | 別人(中央) | 差 |

| **同じ行事の中** | 0.295 | 0.908 | **+0.613** |
| 行事をまたぐ | 0.533 | 0.951 | +0.418 |

平均連結は顔の数の2乗の費用がかかり（未割当 57,770 件を一度に束ねると 26GB）、
同じ日・同じ場所なら**人が目で検算できる**。

[../history/details/2026-10-02-embedding-model-comparison.md](../history/details/2026-10-02-embedding-model-comparison.md)）。

### Phase 3 — 実データでの精度確立（着手中・#35）

詳細は [phase-3-accuracy.md](phase-3-accuracy.md)。

**2026-10-02 に作りを変えた。**

```
いままで:  58,212 件の顔を、126 件の手本と単一空間で照合する（1位正解 64〜70%）
これから:  行事の中で束ねる（容易） → 人がその束にラベルを付ける
```

**機械の仕事を「全体照合（不可能）」から「局所の束ね（容易）」へ移す。**
人間の判断の数は 58,212 から数千へ落ちる。根拠になった測定。

**連続する撮影日が中央2日なので、0歳と15歳を直接照合する必要がない。**
