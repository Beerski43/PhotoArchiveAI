## 手順4 — 取りこぼし率の測り方（実装済み）

### なぜ要るか

既定の閾値 0.4 の根拠（仕様書 §8.3）は **誤一致率だけ**。同一写真に写る別人
同士が閾値を下回る割合は測ったが、**本来紐づくべき顔を落とす率は測っていない。**
閾値を下げれば誤一致は減り取りこぼしは増えるので、片側だけでは決められない。

### 1件抜き交差検証

手動割り当ての顔は**正解が分かっている唯一の集合**。そこから顔を1件抜き、
残りを手本にして `match` と同じ判定へ通し、抜いた顔が元の人物へ戻るかを見る。

```bash
photoarchive evaluate
photoarchive evaluate --thresholds 0.4,0.45,0.5
```

結果は「正解 / 取りこぼし / 誤り」に分かれる。仕様は §8.5、実装は
`src/photoarchive_ai/evaluation.py`。**DBには書かない。**

### 測定が甘く出ないようにしていること

- **同じ写真に写る同一人物の顔を手本から外す**（既定）。抜いた顔とほぼ同じ
  手本が残れば必ず当たる
- **自分の人物の手本が残らない顔は評価から外す。** 手本1件の人物がこれに
  当たり、取りこぼしに数えると率が実態より悪く出る

### 残る限界

連写のように似た手本が**別のファイル**にあると、正解は実運用より甘く出る。
同じ写真かどうかでしか近さを見ていない。実データの数字を見たうえで、
撮影日時での除外が要るかを判断する。

**手本そのものが「人が判別できた顔」に偏っている。** 小さい顔・横向き・ぶれた顔は
GUI で人物を選べないので手本にならないが、`match` の候補にはそれが含まれる。
**この測定は難しい側の顔を母集団から外している**ので、実運用の取りこぼし率は
ここで出る数字より悪くなる。**方向は必ずこちら側**なので、取りこぼしが少なく
見えても閾値を締める根拠にはならない。

## 手順4の判断基準（測ってから決める）

**実測値は必ず甘い側に出る**（上の「残る限界」）。取りこぼしが少なく見えても、
それは閾値を締めてよい根拠にはならない。

| 実測 | 取る手 |
|---|---|
| 取りこぼしが多く、誤りがほぼ0 | 0.45 へ緩める |
| 取りこぼしも誤りも多い | 閾値ではなく手本の枚数・多様性（年代・角度）を疑う |
| 誤りが目立つ | 0.4 を維持するか、マージンを上げる |

**誤って割り当てるほうが、取りこぼすより害が大きい。** 取りこぼした顔は未割当の
まま残るだけだが、誤りは手作業でのやり直しになる。迷ったら厳しい側に倒す。

## 手順5 — `family_only` の決着

閾値 0.4 で切ると `assign_score`（`distance_to_similarity`）の下限が 33.3 に
なるため、`family_score > 0.0` という条件が「割り当てが1つでもあれば通る」と
同じ意味になっている。手順4で閾値が決まってから、しきい値そのものを見直す。
