## #27 — YAML 化

- `config/app_settings.yml` と `config/rule.yml`。サンプルも `*.sample.yml`
- **古い `app_settings.json` は読まない。** 残っているだけなら WARNING で変換を促し、
  CLI と GUI は「DB のパスが要る」の代わりにそのことを言う
- `.json` のルールは止める
- 手元の設定は 2026-10-10 に変換した（元の JSON は `data/config-json-backup-20261010/`。
  `develop` の旧コードでも動くよう、**マージまでは `config/` にも JSON を残してある**）

## #24 — 検出元の複数指定

- 設定は `source_roots:`（配列。古い `source_root:` も読む）。`--source` は何度でも書ける
- 根ごとに走査し、消えた行の削除と2割の安全弁も根ごと。**入れ子の根は止める**
- `ScanRoot`（v7）に走査し終えた根を書く。年フォルダだけの走査は書かない。設定に根が
  無ければ `scan` / `select` / GUI は記録を使う。**移行では推定しない**
- GUI は根が2つ以上なら `<根の名前>/<相対>`。`select` は含む根からの相対
- 実データの複製で v6 → v7 を流した（2026-10-10）: 2.3 秒・Media 70,297 / Face 58,606 / 手動 10,753 件がそのまま
- 手元の設定に根を2つ書いた（`source_roots`。マージまでは旧コード用に `source_root` も残す）
- **マージ後に利用者がすること**: `photoarchive migrate`（版7）→ `photoarchive scan`
  （根が記録される。差分スキャンなので読み直しは変わったファイルだけ）

実データの根は2つ（2026-10-02 に数えた。`Media.path` の接頭辞で数え直せる）。
`/mnt/nfs/nanoPi-NEO2/suzuki/Photo` と `/mnt/nfs/nanoPi-NEO2/share/photo/natsuTemp/な携帯`。
**共通の親（`/mnt/nfs/nanoPi-NEO2`）で走査すると他家の写真まで入る。** 根は推定しない。

## #26 — HEIC を外す（設計は Issue のコメント）

実データの HEIC はすべて `な携帯` 側で、その根の 33%（2026-10-10。`sqlite3` で
`SELECT COUNT(*) FROM Media WHERE lower(path) LIKE '%.heic'`）。**2割の安全弁に掛けない
削除の経路が要る。**
